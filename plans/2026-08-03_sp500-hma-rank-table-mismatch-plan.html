HMA Rank-Table Mismatch Plan

Scope

  • Target HMA configs:
  • /Users/donaldpg/pyTAAA_data/sp500_hma/pytaaa_sp500_hma.json
  • /Users/donaldpg/pyTAAA_data/naz100_hma/pytaaa_naz100_hma.json
  • Do not change rank/weight computation engines.
  • Keep behavior unchanged for naz100_pine, naz100_pi, and sp500_pine JSON files.

Diagnosis Summary

  • The table is generated in functions/output_generators.py by write_rank_list_html.
  • Wt (mo start) comes from monthgainlossweight[:, month_start_idx].
  • Wt (today) and Rank (today) are recomputed with a Sharpe + daily-signal path in the HTML writer.
  • For SP500 HMA, upstream weighting uses equal_weight via UnWeightedRank_2D, not the Sharpe path.
  • For Naz100 HMA, upstream weighting is abs_sharpe_weight, but the table still recomputes "today" from a different path than the monthly-held weight matrix used for month-start.
  • Therefore, month-start columns and today columns are sourced from different selectors, which causes mismatch in HMA pages (including first trading day checks).

Evidence

  • SP500 HMA HTML shows month-start weights of 0.333 for three symbols while today weights are 0.111 across a larger set.
  • Naz100 HMA HTML also shows rank/weight mismatches in the same table section.
  • Path-case is not the issue on this machine; uppercase/lowercase directory variants resolve to the same file content.

Fix Strategy (Scoped)

  • Add a display-only branch in write_rank_list_html, activated when:
  • uptrendSignalMethod == HMAs and stockList is SP500 or Naz100.
  • In that branch, source Wt (today) directly from monthgainlossweight[:, -1].
  • Keep Wt (mo start) from monthgainlossweight[:, month_start_idx].
  • Derive both rank columns from their corresponding weight vectors using one deterministic ordering rule.
  • If month_start_idx == last_index (first trading day), enforce equality by construction:
  • Rank (start of month) == Rank (today) and Wt (mo start) == Wt (today).
  • Leave existing display logic unchanged for non-HMA JSONs.

Deterministic Display Ordering Rule

  • Primary key: positive weight first.
  • Secondary key: weight descending.
  • Tertiary key: symbol ascending (stable tie-break).
  • Exclude CASH from ranked positions, or place it at bottom with zero rank.

Validation Plan

  • SP500 HMA and Naz100 HMA first-trading-day checks: confirm month_start_idx equals last index.
  • Confirm exact equality of rank and weight month-start vs today columns.
  • Regression checks: naz100_pine, naz100_pi, and sp500_pine remain unchanged.
  • Run static error checks and regenerate rank-list HTML for spot verification.

Files To Change (Planned)

  • functions/output_generators.py in write_rank_list_html.

Non-Goals

  • No changes to UnWeightedRank_2D, sharpeWeightedRank_2D, or delta_rank_sharpe_weight_2D.
  • No changes to backtest/trade computation engines.
